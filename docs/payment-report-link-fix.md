# 운영진 대시보드 송금 신고 링크 오류 수정

기준: 2026-09-05. 기존 마이페이지·로그아웃 미커밋 변경은 보존한다.

## 원인

- 대시보드의 ‘확인하러 가기’와 ‘최근 송금 신고 전체보기’가 예시 주소인 `/admin/fees/7/payments`로 고정되어 있었다.
- 운영 서버를 읽기 전용으로 확인한 결과 회비 차수 7은 없고, 확인 대기 신고 2건은 행사 1의 참가비였다.
- 프론트가 `GET /admin/dues-rounds/7/payments`를 호출하면서 실제로 없는 회비 차수에 대한 404가 발생했다.
- 기존 화면 테스트도 고정 주소를 정답으로 검증하고 있어서 회비 없는 운영 데이터 조건을 놓쳤다.

## 변경

- 대시보드의 두 링크를 `/admin/payment-reports`로 교체하고 운영진 메뉴에 ‘송금 신고’를 추가한다.
- `GET /api/v1/admin/payment-reports`: STAFF/ADMIN만 접근, 행사비·회비의 REPORTED 항목 전체 반환. 최근 신고 시각 내림차순, 같은 시각은 납부 ID 순.
- 기존 납부 행 응답에 `source`(유형·실제 ID·제목)를 추가해 행사 참가자 또는 해당 회비 차수로 정확히 연결한다.
- 통합 목록은 부원·입금자·행사/회비명 검색, 기존 승인·반려 API, 처리 후 목록·대시보드 캐시 갱신을 사용한다.
- 회비 차수가 없거나 신고가 없으면 정상적인 빈 상태를 제공한다. 대시보드 미리보기의 10건 제한은 통합 목록에 적용하지 않는다.
- 잘못된 과거 회비 주소는 404 원인과 통합 목록 복귀 링크를 표시한다.
- 환경 변수·DB 스키마 변경 없음. 운영 DB 변경이나 실제 신고 승인·반려는 수행하지 않는다.

## 회귀 검증

- 프론트: 회비 7 없이 대시보드 → 행사 신고 이동, 두 링크 주소, 행사비·회비 혼합 목록, 승인·반려 후 제거, 빈 상태, 구 회비 주소의 404 안내.
- 백엔드: 실제 회비 번호 변경, 회비 자체가 없는 데이터, 미납·확정 건 제외, 운영진 권한, 처리 후 건수 일치, 10건 초과 조회.
- 실제 API E2E: 사용자 신고 → 대시보드 ‘확인하러 가기’ → 행사비 승인 → 참가자 화면에서 납부 완료 확인.

이 문서의 변경은 로컬 구현 기준이며 커밋·푸시·운영 배포는 별도다.

검증 결과: 백엔드 53개(실패·스킵 없음, PostgreSQL Testcontainers 포함), 프론트 22개, 실제 API E2E 2개 통과. 타입 검사·프로덕션 빌드·git diff 공백 검사 통과. 이전 마이페이지·로그아웃 변경을 함께 포함한 작업 트리에서 검증했다.
