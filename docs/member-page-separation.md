# 회원 홈·행사·납부 화면 분리

기준일: 2026-09-05

## 화면 구성

- `/home`: 다가오는 행사 최대 3건 → 내 활동 요약 → 확인이 필요한 납부 최대 3건. 행사/납부 전체보기로 독립 목록 이동.
- `/events`: 기존 API가 제공하는 공개(PUBLISHED) 행사 목록. 시작 시각 순 정렬, 행사명·요약·장소 검색, 신청/미신청/취소 필터, 참여 여부 표시.
- `/payments`: 본인 납부 내역 전체. 갱신 시각 역순, 제목 검색, 행사비/회비 구분, 미납·반려·확인 대기·납부 완료·환불·취소·납부 불필요 필터.
- `/events/:eventId`, `/payments/:paymentId`: 기존 상세 화면 유지. 목록 복귀 링크와 하단 메뉴의 선택 상태 연결.
- `/mypage`: 행사 확인/내 납부 내역 링크를 각각 새 경로로 연결.

홈 ‘참여 중인 행사’는 `/events?participation=JOINED`, ‘입금 확인 대기’는 `/payments?status=REPORTED`, ‘납부 필요’는 `/payments?status=NEEDS_PAYMENT`로 이동한다. 납부 필요는 UNPAID와 REJECTED를 포함한다.

## 탐색 및 호환

- 필터를 URL 검색 파라미터에 저장하여 새로고침·브라우저 뒤로 가기 시 유지한다.
- 이전 `/home#events`, `/home#payments` 북마크는 새 목록 주소로 replace 이동한다.
- 페이지 경로 변경 시 스크롤을 맨 위로 초기화한다. 필터 변경만으로는 스크롤을 초기화하지 않는다.
- 회원 승인 및 로그인 접근 제어는 기존 MemberGate를 그대로 사용한다.
- 기존 API와 캐시 키(`events`, `my-payments`)를 재사용하므로 참가·송금 신고 이후 목록도 갱신된다.
- 백엔드, DB 스키마, 환경 변수 변경 없음. 새로운 ‘종료된 행사 조회’ API는 이번 범위에 포함하지 않는다.

## 검증

- 프론트엔드 33개 테스트 통과: 메뉴 분리, 상세 메뉴 선택 상태, 참여 필터·검색, 완료/환불/취소 납부 조회, 3건 홈 요약, 해시 주소 호환, 인증 차단, 오류 재시도.
- 실제 Spring API E2E 3개 통과: 모바일 메뉴 이동·필터·뒤로 가기·새로고침과 기존 송금/운영진/로컬 로그인 흐름.
- 390px 모바일 행사·납부와 1280px 데스크톱 납부 스크린샷 검수. 320px·390px 납부 화면 가로 넘침 없음.
- TypeScript 검사 및 프로덕션 빌드 통과. 로컬 구현 기준이며 커밋·푸시·배포는 별도.
