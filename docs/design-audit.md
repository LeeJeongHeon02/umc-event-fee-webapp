# D:Club UI/UX 디자인 감사

> 상태: 개선 전 감사 · 2026-09-05  
> 대상: 회원 웹앱, 운영진 센터, 로그인·온보딩·대기 상태  
> 범위: 구현 변경 없음. 이 문서는 다음 디자인 시스템과 화면 개선의 기준이다.

## 1. 감사 방법과 신뢰도

- 운영 도메인의 익명 로그인 화면을 390px, 768px, 1440px 뷰포트로 확인했다. 로그인 세션을 새로 만들거나 운영 데이터를 바꾸지 않았다.
- 회원·운영진의 인증 필요 화면은 현재 배포 소스, 단위/E2E 테스트의 실제 API 캡처(회원 홈 390px, 납부 목록 1280px, 행사 상세 1280px, 행사 관리 390px)를 함께 검토했다.
- 768px 회원·운영진의 실제 로그인 후 캡처는 다음 시각 QA 단계에서 별도로 수집한다. 따라서 이 문서의 768px 평가는 현재 반응형 규칙과 컴포넌트 구조에 근거한 설계 감사다.
- 확인한 대표 흐름: 로그인 → 회원 홈 → 행사/납부 목록 → 행사 상세 → 운영진 대시보드 → 행사 관리 → 참가자·납부 관리.

## 2. 요약

현재 UI는 차분한 오프화이트, 검정, 라임 포인트와 정보 카드 패턴을 일관되게 사용한다. 회원용 모바일 홈은 이미 핵심 행동(행사 확인, 납부 확인)을 한 화면에서 찾을 수 있고, 운영진도 수납·송금 신고를 빠르게 파악할 수 있다.

다만 디자인 언어가 **회원용 모바일 제품**, **넓은 화면의 웹앱**, **운영진 백오피스** 사이에서 충분히 분리되지 않았다. 같은 카드·큰 라운드·강한 라임을 모든 계층에 반복하면서 정보의 우선순위가 약해지고, 768px 전후와 운영진 모바일 내비게이션에서 구조적 문제가 나타난다. 다음 단계는 화면을 꾸미는 작업보다 토큰, 레이아웃, 테이블 반응형, 상태 패턴을 먼저 정리해야 한다.

## 4. 발견 사항

### 4.1 색상, 글꼴, 간격, 모서리, 그림자

**유지할 점**

- `--ink`, 오프화이트 표면, muted 텍스트, 상태 배지의 녹색·노랑·파랑·빨강은 역할이 명확하다.
- Pretendard 우선 폰트 스택과 한글의 촘촘한 자간은 제품 문서 성격에 잘 맞는다.
- `4/8px`에 가까운 간격과 44px 이상 필터 입력 높이는 모바일 조작성의 좋은 기반이다.

**문제**

1. 반경이 8, 9, 11, 12, 13, 14, 15, 16, 17, 18, 20, 22, 24, 30, 32px로 분산돼 있다. 카드·입력·버튼의 위계가 형태로 구분되지 않고 모두 부드러운 박스로 보인다.
2. 그림자는 카드 hover, 떠 있는 회원 메뉴, 운영진 하단 메뉴에서 서로 다른 강도와 방향으로 사용된다. 기본 카드까지 떠 보이게 하면 데이터 중심 화면의 밀도가 떨어진다.
3. 라임은 브랜드 강조, 선택 탭, 운영진 활성 메뉴, 알림 포인트, 수납 진행에 동시에 쓰인다. 특히 운영진의 전체 라임 패널은 `필요한 조치`와 일반적인 선택 상태의 구분을 약화한다.
4. 본문 9~11px, 헤더 34~52px가 한 화면에 공존한다. 운영진 표의 9px 헤더와 10px 데이터는 실제 업무용 화면에서 읽기 어렵다. 숫자는 크지만 설명 라벨이 작아 의미를 빠르게 해석하기 어렵다.

**개선 방향**

- 반경 4단계만 사용한다: `8 / 12 / 16 / 24px`. 표·입력은 8 또는 12px, 기본 카드 16px, 큰 영역만 24px.
- 그림자는 떠 있는 레이어(모달, 팝오버, 모바일 내비게이션)에만 사용하고 기본 카드는 테두리와 배경 차로 분리한다.
- 라임은 1차 행동과 제한된 핵심 지표에만 남긴다. 선택 메뉴는 중성 배경 + 텍스트 강조를 기본으로 한다.
- 최소 본문 14px, 보조 텍스트 12px, 표 데이터 13px을 기준으로 재정의한다. 10px 이하 글자는 배지 안의 짧은 메타데이터에 한정한다.

### 4.3 정보 위계와 장식

- 회원 홈은 `다가오는 행사 → 활동 요약 → 납부` 순서가 실제 사용자 흐름과 대체로 맞는다. 다만 환영 문구, 날짜 카드, 요약 카드가 모두 첫 화면의 시선을 경쟁한다. 미납이 있을 때는 환영 영역보다 납부 행동을 먼저 보이게 해야 한다.
- 행사 카드는 날짜 블록, 참가비, 상태 배지, 화살표, 제목, 장소·인원을 모두 포함한다. 핵심인 제목·일시·내 참여 상태를 먼저 읽게 하고, 장소·참가 인원은 보조 행으로 낮춘다.
- 운영진 대시보드의 거대한 반투명 `!` 장식은 실제 상태 정보보다 시선을 끈다. 수납률·송금 신고는 숫자와 명확한 CTA만으로 충분하다.
- 로그인 화면의 orb, 회전 카드, 블러 효과는 서비스 기능과 무관한 장식이다. 브랜드 소개 목적이라면 한 가지 시각적 모티프만 남기고, 인증 화면에서는 신뢰·간결성을 우선한다.
- 영어 eyebrow가 화면마다 사용되지만, 한국어 기반 업무 앱에서 의미를 추가하지 않는 경우가 많다. 제품의 범주를 구분하는 곳에만 제한하고, 나머지는 한국어 제목과 짧은 설명으로 정리한다.

### 4.4 상태·권한·확인 흐름

**이미 있는 기반**

- 공통 로딩(`LoadingState`)과 오류(`ErrorState`)가 있고 주요 목록·상세 조회에 적용됐다.
- 송금 상태는 `미납 / 확인 대기 / 납부 완료 / 반려 / 환불`로 배지화되어 있다.
- 온보딩 미완료, 승인 대기, 정지 계정, 운영진 권한 게이트가 구현돼 있다.

**보완할 점**

1. 전역 오류는 재시도 위치와 실패 원인을 맥락에 맞게 보여주지 않는다. 일부 `ErrorState`에는 재시도 버튼이 없고, 로그인 만료·권한 부족·네트워크 실패가 같은 어조로 보일 가능성이 있다.
2. 운영진의 승인·반려·환불 같은 비가역성 높은 작업은 행 내부의 작은 버튼 중심이다. 처리 대상, 금액, 처리 결과, 되돌릴 수 없는 영향이 확인 단계에서 더 선명해야 한다.
3. 빈 상태는 홈에는 친절하게 있으나 운영진 목록·검색 결과에서는 주로 한 줄 메시지다. 신규 운영진이 다음 행동(행사 만들기, 회비 차수 만들기, 필터 초기화)을 알기 어렵다.
4. 권한 없는 운영진 메뉴는 숨겨져 있지만, 권한 차이와 요청 방법을 설명하는 UI가 없다. `ADMIN 전용` 기능은 숨김보다 읽기 전용 진입점과 안내가 운영 교육에 유리할 수 있다.
5. 로딩은 큰 빈 영역의 스피너 하나다. 목록·대시보드에는 구조를 유지하는 skeleton이 더 적합하다.

### 4.5 접근성·사용성

- 일반 버튼, 필터 입력, 목록의 최소 높이는 대체로 적절하다. `focus-visible`, `prefers-reduced-motion`, `sr-only` 적용도 좋은 기반이다.
- 색만으로 상태를 전달하지 않도록 배지 텍스트가 있어 좋은 편이다. 다만 운영진 모바일에서 상태 배지를 숨기는 규칙이 있어 상태 파악이 더 어려워진다.
- 긴 이름은 일부 카드에서 한 줄 말줄임 처리된다. 행사명·계좌명·Markdown 표는 줄바꿈 또는 상세 진입에서 전체 텍스트가 반드시 확인되어야 한다.
- Markdown 표에는 가로 스크롤 영역이 있으나, 행사 상세의 CTA 겹침이 먼저 해결돼야 한다.
- 대시보드의 날짜가 `2026. 09. 01`로 고정되어 있다. 최신 데이터라는 신뢰를 해치므로 `오늘` 또는 실제 갱신 시각으로 표시해야 한다.

| `ConfirmActionDialog` | 브라우저 기본 confirm, 행 버튼 | 승인·반려·취소·환불의 영향, 대상, 금액, 완료 토스트를 표준화 |
| `StatusBadge` | 현재 구현됨 | 색상·아이콘·문구·보조 설명을 상태 토큰에 연결 |

## 6. 유지·제거 기준

### 유지

- 검정/오프화이트 기반의 절제된 표면과 짧은 라임 포인트
- 회원용 4개 핵심 메뉴와 명확한 현재 위치 표시
- 행사 날짜를 빠르게 읽게 하는 날짜 블록
- 납부 상태의 텍스트 배지와 금액 우선 표기
- 운영진의 사이드바 + 데이터 패널이라는 데스크톱 정보 구조
- 전역 포커스 표시, reduced motion, 상태별 오류·빈 상태의 기본 구조

### 제거 또는 축소

- 인증 화면의 다중 orb·회전 카드·과도한 블러
- 운영진 주의 패널의 거대한 `!` 장식
- 모든 컨테이너에 적용된 큰 라운드와 hover 부양 효과
- 의미가 약한 영어 eyebrow의 반복
- 데스크톱까지 유지되는 모바일용 고정 CTA
- 동일한 중요도로 나열되는 회원 홈의 3개 요약 카드
- 5열에 6개를 넣는 운영진 모바일 메뉴

## 7. 개선 우선순위와 완료 기준

### P0 — 신뢰와 업무 완료를 막는 문제

1. 행사 상세 CTA 겹침을 수정하고 390/768/1440px에서 본문·표·버튼이 겹치지 않는지 자동 캡처로 검증한다.
2. 운영진 모바일/태블릿 내비게이션을 재설계한다. 모든 메뉴가 잘리지 않고 44px 이상 터치 영역을 가져야 한다.
3. 운영진 테이블의 모바일 카드형 표현과 승인 행동의 확인 단계를 설계한다.

### P1 — 제품의 일관성

4. 색상, 타이포그래피, 간격, 반경, 그림자, 상태 토큰을 정의하고 기존 CSS 값의 직접 사용을 줄인다.
5. `PageHeader`, `MetricCard`, `FilterBar`, 상태 화면을 공통화한다.
6. 홈의 `납부 필요`를 행동 우선 카드로 전환하고, 빈 상태에 다음 행동을 넣는다.
7. 실제 날짜·갱신 시각을 사용한다.

### P2 — 완성도

8. 인증·온보딩의 장식을 축소하고 신뢰·절차·오류 안내를 강화한다.
9. 수납률, 이벤트 카드, 통계 카드의 밀도를 조정한다.
10. 키보드 순서, 색 대비, 긴 텍스트, 스크린 리더 레이블을 화면별로 검수한다.

## 9. 다음 시각 QA 체크리스트

- 각 대표 화면을 390×844, 768×1024, 1440×960으로 캡처한다.
- 가로 스크롤은 데이터 표·Markdown 표 안에서만 허용한다.
