# D:Club 디자인 시스템

> 상태: v0.1 · 디자인 감사 기반 초안 · 2026-09-05  
> 연관 문서: [UI/UX 디자인 감사](./design-audit.md)  
> 적용 범위: React 회원 웹앱, 운영진 센터, 인증·온보딩·상태 화면

## 1. 목적

D:Club은 동아리원을 위한 행사·납부 확인 서비스이면서 운영진을 위한 수납 업무 도구다. 이 시스템은 화면마다 장식을 더하는 대신 정보의 중요도와 업무 행동을 일관되게 표현하는 기준이다.

목표는 다음과 같다.

1. 동아리원은 행사 신청과 납부 필요 여부를 빠르게 찾고 처리한다.
2. 운영진은 많은 회원·행사·납부 상태를 작은 오류 가능성으로 관리한다.
3. 모바일, 태블릿, 데스크톱에서 같은 정보가 역할에 맞는 밀도로 보인다.

## 2. 디자인 원칙

### 업무가 장식보다 먼저

한 화면에는 가장 중요한 행동을 하나만 둔다. 배경 장식, 불필요한 그래픽, 과도한 hover 효과는 정보 이해나 행동 완료에 기여할 때만 사용한다.

### 회원에게는 친절하게, 운영진에게는 밀도 높게

회원 화면은 일정, 금액, 다음 행동을 읽기 쉽게 안내한다. 운영진 화면은 많은 상태를 비교·검색·처리해야 하므로 같은 카드 반복보다 표, 필터, 요약, 빠른 행동을 우선한다.

### 상태는 색이 아니라 문장으로 전달

색상은 보조 수단이다. 납부·환불·승인 상태는 항상 읽을 수 있는 짧은 배지와 필요한 다음 행동을 함께 제공한다.

### 반응형은 축소가 아니라 재배치

모바일에서 데스크톱 UI를 단순히 줄이지 않는다. 표는 요약 카드 행으로, 복잡한 메뉴는 우선 메뉴와 더보기로, 보조 정보는 상세 화면으로 재배치한다.

### 평온한 기본, 명확한 주의

기본 표면은 중성 색과 얇은 경계로 안정감을 준다. 라임은 한 화면의 1차 행동 또는 제한된 핵심 지표에만 사용한다. 오류·미납·위험 행동에는 해당 상태 색상을 사용한다.

## 3. 기반 토큰

구현 시 아래 값은 CSS Custom Property로 관리한다. 개별 컴포넌트에 임의의 색상, 반경, 그림자 값을 추가하지 않는다.

### 색상

| 토큰 | 값 | 용도 |
| --- | --- | --- |
| color-text-primary | #171717 | 제목, 본문, 1차 버튼 |
| color-text-secondary | #706F69 | 보조 설명, 레이블 |
| color-text-tertiary | #92918C | 비활성·보조 메타데이터 |
| color-surface-canvas | #F6F5F0 | 앱 배경 |
| color-surface-default | #FFFFFF | 카드, 입력, 표 |
| color-surface-subtle | #F3F2ED | 구분 영역, 선택 전 배경 |
| color-border-default | #DEDDD7 | 기본 경계 |
| color-brand | #D8FF42 | 1차 강조, 선택된 핵심 동작 |
| color-brand-strong | #B8E51A | 진행 바, brand hover |
| color-info | #2B5AA6 | 확인 대기, 정보 |
| color-success | #147A52 | 완료, 공개, 성공 |
| color-warning | #8A6812 | 미납, 마감, 주의 |
| color-danger | #C63F32 | 반려, 취소, 오류, 파괴 행동 |

상태 배경은 텍스트 대비를 보장하는 연한 톤을 사용한다. 한 상태의 색상이 버튼, 전체 패널, 알림점, 진행 바에 동시 사용되지 않도록 한다.

### 타이포그래피

| 토큰 | 값 | 적용 |
| --- | --- | --- |
| font-caption | 12px | 보조 메타데이터, 표 헤더 |
| font-body | 14px | 기본 본문 |
| font-body-lg | 16px | 입력값, 읽기 중심 본문 |
| font-title-sm | 20px | 카드·섹션 제목 |
| font-title-md | 28px | 페이지 제목 |
| font-title-lg | 36px | 핵심 랜딩·인증 제목 |

- 기본 본문은 14px 이상, 모바일 입력값은 16px을 사용한다.
- 표 데이터는 13px 이상을 사용한다.
- 숫자 지표는 고정폭 숫자 스타일을 사용해 비교하기 쉽게 한다.
- 영어 eyebrow는 제품 범주가 실제로 필요한 곳에만 사용한다. 기본은 한국어 제목과 한 줄 설명이다.

### 간격·크기·반경

| 분류 | 값 |
| --- | --- |
| 간격 | 4 / 8 / 12 / 16 / 24 / 32 / 48px |
| 반경 | 8 / 12 / 16 / 24px |
| 컨트롤 높이 | 36 / 44 / 52px |

- 입력과 테이블 안의 작은 버튼은 8 또는 12px 반경을 사용한다.
- 일반 카드와 목록 행은 16px, 큰 구역과 인증 패널은 24px을 사용한다.
- 핵심 터치 대상은 최소 44×44px이다.

### 그림자·레이어

기본 카드에는 그림자를 사용하지 않는다. 그림자는 모바일 떠 있는 내비게이션, 팝오버, 모달처럼 표면이 실제로 떠야 할 때만 사용한다. hover는 경계 색상 변경을 기본으로 하고 이동 효과는 2px을 넘지 않는다.

## 4. 레이아웃과 반응형

| 구간 | 폭 | 회원 화면 | 운영진 화면 |
| --- | --- | --- | --- |
| Mobile | 0–719px | 상단 바 + 4개 하단 메뉴, 단일 열 | 우선 메뉴 + 더보기, 카드형 데이터 행 |
| Tablet | 720–959px | 상단 메뉴 또는 compact rail | 접히는 사이드바 또는 2행 메뉴 |
| Desktop | 960px 이상 | 상단 수평 메뉴, 최대폭 1120px | 248px 사이드바, 넓은 표와 고밀도 패널 |

### 콘텐츠 폭

- 회원 목록·상세는 최대 960px을 기준으로 한다. 넓은 화면의 주요 행동은 본문 우측 보조 열 또는 정적 CTA로 배치한다.
- 회원 홈은 최대 1120px으로 넓힌다. 1440px 이상에서는 이벤트·납부를 무리하게 2열화하지 않고 요약 영역만 넓힌다.
- 운영진은 사이드바를 제외한 작업 영역 최대 1380px을 사용한다.
- 모바일 고정 하단 요소가 있다면 본문 끝에 요소 높이, safe-area, 16px을 합한 여백을 둔다.

### 내비게이션

#### 회원

- Mobile: 홈, 행사, 납부, 마이 4개를 하단에 고정한다.
- Tablet: 콘텐츠를 가리는 떠 있는 바 대신 상단 수평 메뉴를 우선 검토한다.
- Desktop: 상단 수평 메뉴를 사용하며 현재 메뉴만 경계와 중성 표면으로 표시한다.

#### 운영진

- Desktop: 대시보드, 송금 신고, 행사 관리, 회비 관리, 회원 관리, 환불 관리를 사이드바에 표시한다.
- Mobile: 대시보드, 신고, 행사, 회비, 더보기 5개를 기본으로 하고 회원·환불은 더보기에서 제공한다.
- Tablet: 6개 메뉴를 좁은 하단 바에 넣지 않는다. 접히는 왼쪽 rail 또는 2행 메뉴 중 하나를 선택한다.

## 5. 컴포넌트 규격

### PageHeader

모든 목록·상세·운영진 페이지는 같은 구조를 사용한다.

1. 선택: 뒤로 가기
2. 선택: 범주 레이블
3. 제목과 선택: 1차 행동
4. 한 줄 설명 또는 최신 갱신 시각

제목은 페이지의 유일한 h1이다. 날짜는 하드코딩하지 않고 실제 현재 날짜 또는 데이터 갱신 시각을 사용한다. 모바일에서는 1차 행동을 제목 아래 전폭 버튼으로 옮길 수 있다.

### Button

| Variant | 용도 | 표현 |
| --- | --- | --- |
| primary | 한 화면의 핵심 완료 행동 | 검정 배경, 흰 텍스트 |
| secondary | 되돌릴 수 있는 보조 행동 | 흰 배경, 경계 |
| brand | 즉시 행동이 필요한 강조 | 라임 배경, 검정 텍스트 |
| danger | 취소·삭제·반려·환불 처리 | 빨강 텍스트/경계 |
| ghost | 탐색·보조 행동 | 배경 없음, 충분한 터치 영역 |

- 같은 화면에 primary는 한 개만 둔다.
- 비가역 행동은 확인 다이얼로그를 거친다.
- 진행 중에는 버튼 텍스트와 접근 가능한 진행 상태를 바꾸고 중복 실행을 막는다.

### MetricCard

정보형, 행동형, 위험형 세 가지 variant를 사용한다.

레이블, 선택 상태 배지, 주요 숫자 또는 금액, 보조 설명 또는 다음 행동의 순서를 따른다.

- informational: 중성 표면, 단순 현황.
- actionable: 미납·확인 대기처럼 행동이 필요할 때. 클릭하면 해당 필터 결과로 이동.
- critical: 오류·긴급 상태에만 danger 톤을 사용.
- 회원 홈에서는 행동이 필요한 카드 하나를 전폭으로 우선 배치하고, 나머지는 작은 보조 지표로 둔다.

### DataCard와 DataTable

- 회원용 행은 제목 → 금액/일시 → 상태 → 보조 정보 순서를 사용한다.
- 운영진 데스크톱 표는 대상 → 상태 → 금액 → 시간 → 행동 순서로 열을 배치한다.
- 700px 이하 운영진 표는 카드형 행으로 전환한다. 첫 줄에는 대상·상태, 둘째 줄에는 금액·일시, 마지막 줄에는 승인/반려 행동을 둔다.
- 가로 스크롤은 Markdown 표, 내보내기용 전체 데이터처럼 대체 표현이 불가능한 경우에만 허용한다.

### FilterBar

- 검색 입력, 가장 자주 쓰는 상태 필터, 결과 수, 초기화를 한 묶음으로 제공한다.
- Mobile에서는 검색을 첫 줄 전체 폭으로 두고 나머지 필터는 2열까지 허용한다.
- 활성 필터가 있을 때는 결과 수 옆에 현재 조건을 텍스트로 표시한다.
- 필터 변경은 URL 검색 파라미터와 동기화한다.

### StatusBadge

| 상태군 | 예시 | 다음 행동 |
| --- | --- | --- |
| Neutral | 초안, 납부 없음, 부과 취소 | 없음 또는 상세 보기 |
| Warning | 미납, 마감, 환불 대기 | 납부·처리 확인 |
| Info | 송금 확인 대기 | 운영진 확인 대기 |
| Success | 납부 완료, 공개 | 완료 안내 |
| Danger | 반려, 행사 취소 | 사유 확인 또는 재시도 |

배지는 상태를 전달할 뿐 행동을 숨기지 않는다. 반려에는 사유와 재신고 행동을, 확인 대기에는 처리 주체를 함께 제공한다.

### 상태 화면

| 상태 | 필수 요소 | 예시 행동 |
| --- | --- | --- |
| Loading | 현재 영역의 skeleton, 짧은 상태 문장 | 자동 갱신 |
| Empty | 왜 비었는지, 다음 행동 하나 | 행사 만들기, 필터 초기화 |
| Error | 맥락 제목, 사용자가 할 수 있는 조치, 재시도 | 다시 불러오기, 로그인하기 |
| Unauthorized | 권한 이유와 돌아갈 위치 | 회원 화면으로 이동 |
| Pending | 현재 단계, 다음 주체, 예상 행동 | 운영진 승인 대기 |
| Success | 완료된 대상·금액·다음 이동 | 납부 내역 보기 |

목록·대시보드에는 중앙 spinner 하나가 아니라 실제 카드/행 크기와 가까운 skeleton을 사용한다.

### ConfirmActionDialog

송금 승인, 반려, 행사 취소, 환불 완료, 초안 삭제에 사용한다.

1. 행동 제목
2. 대상 이름, 행사명, 금액
3. 영향 설명과 되돌릴 수 있는지 여부
4. 취소와 확인 행동

파괴 행동에는 danger 버튼을 쓰고, 완료 후에는 결과 toast와 변경된 상태를 모두 보여준다.

## 6. 화면별 정책

### 회원 홈

1. 미납 또는 반려가 있으면 최상단에 납부 필요 행동 카드를 둔다.
2. 다음으로 다가오는 행사 1~3개를 보여준다.
3. 참여 중 행사와 확인 대기 건수는 보조 지표로 압축한다.
4. 환영 문구와 날짜는 작고 안정적인 컨텍스트로 유지한다.

### 행사 상세

- 제목, 일시, 장소, 참가비, 신청 상태를 먼저 보여준다.
- 960px 이상에서는 신청 CTA를 본문 흐름의 우측 보조 영역 또는 최하단 정적 영역에 둔다. 본문 위에 고정하지 않는다.
- 960px 미만에서는 CTA를 하단에 고정할 수 있으나 Markdown 표·마감 정보·오류 메시지가 가려지지 않게 본문 여백을 확보한다.
- 긴 Markdown 표는 표 내부에서만 가로 스크롤한다.

### 납부 상세

- 납부 금액과 현재 상태를 첫 화면에 명확히 표시한다.
- 송금 정보는 복사, 송금 실행, 송금 완료 신고 순서로 분리한다.
- 송금했어요는 실제 금융 확인이 아니라 신고 단계임을 문장으로 다시 안내한다.

### 운영진 대시보드

- 최상단은 확인 대기 송금, 미납, 예정 행사처럼 즉시 행동 가능한 정보만 둔다.
- 수납률은 보조 지표다. 거대한 장식 문자보다 수치, 이전 기간 대비, 상세 링크를 우선한다.
- 최근 신고 목록은 대상·금액·상태·처리 행동을 빠르게 읽게 한다.

### 운영진 행사·회비 관리

- 생성·수정은 기본 정보, 일정, 참가비, 안내, 공개 설정의 섹션으로 나눈다.
- Markdown 편집기는 작성·미리보기를 유지하되 모바일에서 하단 메뉴와 겹치지 않게 한다.
- 공개·마감·취소는 상태 변화의 영향과 되돌림 가능 여부를 명확히 표시한다.

## 7. 접근성·콘텐츠 기준

- 키보드 포커스는 항상 3:1 이상 대비의 외곽선으로 보인다.
- 텍스트와 배경의 대비는 WCAG AA를 목표로 한다.
- 아이콘만으로 행동을 전달하지 않는다. 아이콘 버튼에는 접근 가능한 이름을 제공한다.
- 긴 행사명·닉네임·계좌명은 의미 없는 말줄임만 사용하지 말고 상세 화면에서 전체 값을 제공한다.
- 금액은 15,000원, 날짜는 9월 15일 (화) 19:00처럼 일관된 현지 형식을 사용한다.
- 금융·권한·취소 상태에서는 모호한 표현보다 정확한 결과를 쓴다.

## 8. 구현 순서

1. 전역 토큰을 정의하고 직접 지정된 색상·반경·그림자를 토큰으로 교체한다.
2. 행사 상세의 데스크톱 CTA 겹침과 운영진 모바일 메뉴를 먼저 수정한다.
3. 회원 홈을 행동 우선 구조로 재설계한다.
4. PageHeader, MetricCard, FilterBar, 상태 화면을 공통 컴포넌트로 만든다.
5. 운영진 테이블의 모바일 카드 행과 ConfirmActionDialog를 적용한다.
6. 인증·온보딩과 나머지 회원·운영진 화면에 확장한다.

각 단계는 390×844, 768×1024, 1440×960에서 시각 캡처와 가로 넘침 검사를 통과해야 한다. 기능 API·라우팅·권한 계약을 바꾸지 않는 것을 기본으로 한다.
